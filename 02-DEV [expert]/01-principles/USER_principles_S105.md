================================================================================
ZWECK DIESES DOKUMENTS
================================================================================

Dieses Dokument beschreibt die Leitprinzipien der USER-Reihe im R+MUNI Blueprint.

Es erklärt:
  - Was die USER-Reihe ist und für wen sie gedacht ist
  - Welche Grundhaltung R+MUNI gegenüber seinen Usern hat
  - Welche Prinzipien für alle USER-Dokumente gelten

Es beschreibt nicht:
  - Wie R+MUNI konkret eingesetzt wird (→ operative Anleitungen)
  - Interne Blueprint-Entwicklung (→ DEV-Reihe)


================================================================================
1. ZWECK UND CHARAKTER DIESER DOKUMENTENREIHE
================================================================================

Die USER-Reihe ist Bestandteil des R+MUNI Blueprints und richtet sich
an alle die R+MUNI in ihrem Unternehmen einsetzen.

Sie beschreibt was User wissen, verstehen und können müssen —
nicht wie das Blueprint-System intern aufgebaut ist.

Kernprinzip:
  Die USER-Reihe übersetzt Blueprint-Konzepte in Anwendersprache.
  Sie setzt kein technisches Vorwissen voraus.
  Sie ist eigenständig lesbar ohne Kenntnis interner Blueprint-Dokumente.

Abgrenzung zu internen Blueprint-Dokumenten:
  Interne Dokumente (Principles, How2, GOV) beschreiben das System
  aus Entwicklerperspektive — mit Blueprint-Terminologie und
  technischer Tiefe.

  USER-Dokumente beschreiben dasselbe System aus Anwenderperspektive —
  mit Alltagssprache, konkreten Beispielen und handlungsorientiertem Fokus.

  Beide Perspektiven sind Teil des Blueprints und ergänzen sich.


================================================================================
2. ZIELGRUPPE
================================================================================

Die USER-Reihe richtet sich an alle User von R+MUNI.

R+MUNI ist kostenlos und für jeden zugänglich.
User ist jeder der R+MUNI nutzt — ohne Bedingung, ohne Kaufakt.

Typisches User-Profil:
  - KMU bis 50 Mitarbeiter (österreichischer Mittelstand)
  - Nicht-technische Anwender ohne Programmierkenntnisse
  - Entscheider und operative Nutzer in einem
  - Gleichgesinnte die strukturiertes Arbeiten schätzen

Für alle User gilt:
  - Alltagssprache ist Pflicht — kein IT-Fachjargon ohne Erklärung
  - Konkrete Beispiele vor abstrakten Prinzipien
  - Schritt-für-Schritt Logik wo immer möglich
  - Keine Vorannahmen über technisches Vorwissen


================================================================================
3. GRUNDHALTUNG GEGENÜBER R+MUNI
================================================================================

R+MUNI ist kostenlos. Das ist keine Marketing-Aussage, sondern Haltung.

Für alle User gilt:
  - Kein Kaufzwang, kein Upgrade-Druck, keine versteckten Kosten
  - Das Tool gehört der Community — Feedback ist erwünscht und wirkt
  - Wer Mehrwert bekommt, darf diesen weitergeben

R+MUNI ist kein Fertigprodukt das man einfach einschaltet.
Es ist ein Werkzeugkasten der Denkarbeit voraussetzt und belohnt.

Wer bereit ist diese Denkarbeit zu leisten bekommt:
  - Strukturierte Unternehmensarchitektur
  - Verbindung von Prozessen und IT in einem System
  - Nachvollziehbare, reproduzierbare Dokumentation
  - Eine Basis für fundierte Entscheidungen


================================================================================
4. GRUNDPRINZIPIEN
================================================================================

4.1 Explizitheit
-----------------
Das zentrale Prinzip von R+MUNI ist Explizitheit.

Explizit bedeutet:
  - Entscheidungen werden ausgesprochen und dokumentiert
  - Annahmen werden benannt — nicht stillschweigend vorausgesetzt
  - Begründungen gehören zur Entscheidung dazu
  - Was nicht dokumentiert ist existiert für das System nicht

Konkret bedeutet das:
  Wer R+MUNI nutzt gewöhnt sich an, Dinge auszusprechen die sonst
  implizit bleiben. Das fühlt sich anfangs aufwändig an —
  es zahlt sich aus sobald das System wächst.


4.2 Stabilität vor Komfort
---------------------------
R+MUNI priorisiert langfristige Stabilität über kurzfristigen Komfort.

Konkret bedeutet das:
  - Manche Wege sind bewusst länger als nötig
  - Abkürzungen die kurzfristig helfen erzeugen langfristig Probleme
  - Strukturdisziplin zahlt sich erst nach Wochen und Monaten aus

Typisches Muster:
  Woche 1:  "Das ist zu aufwändig für so eine kleine Sache"
  Monat 3:  "Gut dass wir das damals sauber gemacht haben"


4.3 Schrittweise Erweiterung
------------------------------
R+MUNI ist für schrittweisen Aufbau konzipiert — nicht für den
großen Wurf von Anfang an.

Konkret bedeutet das:
  - Mit einem Kernbereich starten
  - Diesen vollständig und konsistent aufbauen
  - Erst dann auf weitere Bereiche ausweiten

Empfohlene Einstiegsreihenfolge:
  1. Einen einzigen Kernbereich wählen
  2. Diesen vollständig und konsistent aufbauen
  3. Verstehen wie das System damit umgeht
  4. Konventionen ableiten
  5. Auf weitere Bereiche ausweiten


4.4 Dokumentierte Entscheidung
--------------------------------
Jede wesentliche Entscheidung im System gehört dokumentiert.

Konkret bedeutet das:
  Eine dokumentierte Entscheidung enthält:
  - Was wurde entschieden?
  - Warum wurde so entschieden?
  - Welche Alternativen wurden geprüft und warum verworfen?
  - Was gilt als Voraussetzung für diese Entscheidung?

Was keine Entscheidungsdokumentation ist:
  - "Haben wir so gemacht"
  - Eine fertige Konfiguration ohne Erklärung
  - Eine mündliche Vereinbarung ohne schriftliche Entsprechung


4.5 Kontrolliertes Wachstum
-----------------------------
R+MUNI wächst kontrolliert — nicht organisch.

Konkret bedeutet das:
  Bevor ein neuer Bereich ins System aufgenommen wird:
  - Gibt es bereits eine passende Konvention?
  - Wenn ja — diese übernehmen
  - Wenn nein — bewusst eine neue definieren und dokumentieren


4.6 Offenes Feedback
---------------------
R+MUNI lebt von Feedback aus der Praxis.

Konkret bedeutet das:
  Feedback ist kein Angriff auf das System — es ist Rohstoff für
  Verbesserungen die allen Usern zugutekommen.

  Der definierte Feedback-Kanal:
    https://ims-blueprint-ticketsystem.atlassian.net/helpcenter/RMNP/

  Es gibt keine SLA und kein Versprechen zur Umsetzung.
  Es gibt Offenheit und Ehrlichkeit über Kapazität und Prioritäten.
